# EunoBench ESP32 真板补充测试

本轮完成 **9 个配置、45 次独立复位、1355 条复位级测量记录**。板卡使用 ESP32-D0WDQ6 rev 1.1、4 MB Flash、40 MHz 晶振。各配置单核运行，CPU 设为 240 MHz。Windows 通过 USB 串口连接，WSL Linux 文件系统存放构建与采集证据。

本轮使用 EunoBench 论文固定的上游版本，重建了补充指标专用固件。Zephyr 的两组附加策略重建了调度器和等待队列组合，作者冻结的完整 B1 固件工程未包含在公开审稿包中。本轮数据作为独立的真板实时性面板，原 Overall 的评测口径继续使用论文定义。

## 启动、IRQ 与镜像尺寸

- FreeRTOS 从 `esp_timer` 计时零点到应用入口中位数为 **1299 µs**，五次范围 1297–1301 µs。物理复位沿及其之前的过程在此端点之外。
- Zephyr 基线 fixed-tick 的原生 IRQ offload 入口及往返中位数分别为 **1.780 µs**、**3.382 µs**。每次复位触发 100 次并检查实际 ISR 上下文。TenonOS 图 8 的上下文保存、分派和恢复各阶段需要独立测点。
- ELF 表保留每个已分配分段的地址、分段类型、地址空间和字节数。Flash 中的固件文件大小来自 manifest。加载到 RAM 的分段会占用 RAM，带初值的分段也占用镜像空间。运行时任务栈、堆与 EunoBench 原 allocated RAM 采用各自的计量口径。

## 适用范围与缺测项

- FreeRTOS 的启动日志显示 `v5.2.5-dirty`。SDK 主仓库提交与论文固定版本一致，已核对主仓库跟踪文件，子模块工作树产生 dirty 后缀。
- Zephyr 栈为每个 worker 1280 字节，NuttX 为 1152 字节，FreeRTOS 为 1536 字节。线程、定时器和计时器读取都引入测试应用开销。五次复位的中位数和范围只描述本板、本固件。
- Contiki-NG 的原 cooperative 配置缺少适用的原生抢占线程路径。当前可用的 AliOS Things 固定版本源码仅覆盖 Rhino Linux 主机子集，缺少可重建原实验的 ESP32 BSP。
- RIOT 使用微秒 ztimer 观察短区间，毫秒 ztimer 观察请求到期偏差。其回调运行于 IRQ 上下文，计时精度与其他配置不同。
- 物理复位至首任务就绪、IRQ 架构分段、能耗以及 Mortise/Linux 共置仍待补测。刷写、串口采集和代码重放的证据对应本轮单板原生测试。
